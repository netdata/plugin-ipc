# SOW-0058 - Align Go Modules With Netdata's Go 1.27

## Status

Status: open

Sub-state: approved 2026-10-31; runs after SOW-0045.

## Requirements

### Purpose

Keep plugin-ipc's Go modules on the same Go version as Netdata, the project rule recorded in SOW-0015, so vendored Go code builds the same in both repositories and scanners stop reporting standard-library CVEs fixed in newer Go.

### User Request

SOW-0015 recorded the rule that plugin-ipc Go modules match Netdata's Go version (`go 1.26.0` at the time).

### Assistant Understanding

Facts:

- plugin-ipc: `go 1.26.0` in `src/go/go.mod`, `bench/drivers/go/go.mod`, `tests/fixtures/go/go.mod`; `.github/workflows/codacy-analysis.yml:75` pins `go-version: "1.26.x"`.
- Netdata: `go 1.27.0` in `src/go/go.mod` (`netdata/netdata` default branch and `ktsaou/netdata @ ae9113f2cc`, read 2026-10-31).
- Codacy Cloud on `main` `63919ecb7d`: all 33 open issues are Trivy standard-library findings on `go.mod` (22 high, 9 medium, 2 minor).
- Toolchains: workstation go 1.27.2; Windows test host go 1.26.5; FreeBSD test VM go 1.26.10.

Inferences:

- Moving to `go 1.27.0` clears findings fixed by 1.27.0; findings fixed only in later 1.27.x patches need a newer `toolchain` line or remain until Netdata moves.

Unknowns:

- Which of the 33 findings 1.27.0 clears (re-scan after push).

### Acceptance Criteria

- All three `go.mod` files and the Codacy workflow use Go 1.27; Linux, FreeBSD and Windows Go suites pass with Go 1.27; Codacy findings re-checked and recorded.
