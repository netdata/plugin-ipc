# SOW-0034 - Rust 2024 Migration

## Status

Status: open

Sub-state: Queued behind SOW-0033; preliminary validation evidence identifies the migration surfaces that require full analysis.

## Requirements

### Purpose

Migrate the standalone plugin-ipc Rust crate and every Rust target declared by its manifest to Rust edition 2024 without changing protocol behavior or introducing destructor-order regressions.

### User Request

After completing the surgical Netdata vendor-drift backport first, the user requested a full Rust 2024 migration because Rust 2024 is the durable direction for the project.

### Assistant Understanding

Facts:

- `src/crates/netipc/Cargo.toml` currently selects edition 2021.
- The manifest declares the NetIPC library plus interop and benchmark binaries located under `tests/fixtures/rust/` and `bench/drivers/rust/`.
- Netdata's Rust workspace already uses edition 2024 and Rust 1.91.
- A Rust 2024 compatibility lint check found reserved `gen` identifiers in benchmark drivers.
- The same check found edition-dependent temporary drop-order changes in SHM and UDS connection loops in benchmark and fixture binaries.
- Windows-only library compatibility changes are handled by SOW-0033, but full Windows target validation is still required for an edition migration.

Inferences:

- This work is broader than a manifest edit because edition 2024 changes keyword parsing, unsafe syntax requirements, and temporary drop scope.
- Mechanical suppression of the drop-order lint would be unsafe without proving that session and SHM destructors still run in the intended order.

Unknowns:

- The desired standalone plugin-ipc MSRV after migration; Rust edition 2024 itself does not require adopting Netdata's exact workspace MSRV policy.
- Whether each reported drop-order site is behaviorally neutral or requires an explicit binding/scope change.
- Whether additional Windows-only edition findings appear under the native Windows CI/toolchain.
- Whether README, contributor guidance, CI toolchain declarations, or integration guidance state an edition/MSRV contract that must change.

### Acceptance Criteria

- The standalone Rust manifest selects edition 2024 with an explicitly decided and documented MSRV policy.
- Every library, test, fixture, interop, and benchmark target declared by the manifest builds under edition 2024.
- All Rust 2024 compatibility findings are implemented or explicitly rejected with evidence; none are silenced without a behavioral explanation.
- POSIX Rust tests, coverage requirements, interop, and benchmarks remain valid.
- Native Windows or project-standard Windows validation covers Named Pipe, Windows SHM, typed service, cache, and declared Windows binaries.
- C/Rust/Go protocol and interoperability contracts remain unchanged and validated.
- A same-pattern search and artifact maintenance review cover all Rust targets and public guidance.

- Rust 2024 compatibility lints for the vendored library and its unit tests pass under SOW-0033.

Risks:

- Rust 2024 temporary lifetime changes can alter the order in which failed connection attempts, live sessions, or SHM mappings are dropped.
- Expanding MSRV without an explicit decision can break supported downstream builders.
- POSIX-only validation can miss Windows-gated FFI and transport failures.
- Updating Rust behavior without checking C and Go interoperability can create cross-language release regressions.

## Pre-Implementation Gate

Status: blocked

Problem / root-cause model:

- The standalone crate is edition 2021 while its downstream Netdata workspace is edition 2024. Source-owned library compatibility drift is addressed separately in SOW-0033, but the standalone manifest also compiles benchmark and fixture binaries that contain edition-2024 keyword and temporary-drop-order findings. A safe migration must analyze those runtime lifetimes rather than treating the work as a mechanical manifest change.

Evidence reviewed:

- `src/crates/netipc/Cargo.toml:4` selects edition 2021 and later manifest entries declare interop and benchmark binaries outside the crate directory.
- `bench/drivers/rust/src/main.rs:260,266` and `bench/drivers/rust/src/bench_windows.rs:521,527` use `gen`, which is reserved in edition 2024.
- Rust 2024 compatibility lints report temporary drop-order changes at:
  - `tests/fixtures/rust/src/bin/interop_shm.rs:81`
  - `bench/drivers/rust/src/main.rs:400,441,680,818,968,1007`
- The affected temporaries own `UdsSession` or `ShmContext` values whose `Drop` implementations release transport resources.
- `netdata/netdata @ 01d56fddc20ac4a73ea74da19e49420cab764ad0`, `src/crates/Cargo.toml:66-67`, uses edition 2024 and Rust 1.91.

Affected contracts and surfaces:

- Rust language edition and MSRV policy.
- Rust library, unit tests, interop fixtures, and benchmark binaries.
- POSIX UDS and SHM resource lifetime behavior.
- Windows Named Pipe and SHM compilation/runtime behavior.
- CI toolchain declarations, coverage, interop, and benchmark validation.
- Potential developer and integrator documentation.

Existing patterns to reuse:

- Low-priority Rust validation and coverage scripts under `tests/`.
- Native Windows validation scripts matching the touched transport/API.
- Cross-language interop scripts and benchmark generators.
- Explicit resource-lifetime handling already used in UDS and SHM implementations.

Risk and blast radius:

- Medium: edition migration spans all standalone Rust targets and can change temporary destruction timing.
- No production service, database, configuration, environment, package installation, network, or runtime process changes are expected.
- Keep SOW-0033's exact vendor backport isolated in its own completed commit before this migration begins.
