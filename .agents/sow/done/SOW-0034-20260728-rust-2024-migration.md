# SOW-0034 - Rust 2024 Migration

## Status

Status: completed

Sub-state: Delivered and validated on POSIX, native Windows, latest stable
Rust, and the exact Rust 1.91 MSRV.

## Requirements

### Purpose

Migrate the standalone plugin-ipc Rust crate and every Rust target declared by its manifest to Rust edition 2024 without changing protocol behavior or introducing destructor-order regressions.

### User Request

After completing the surgical Netdata vendor-drift backport first, the user requested a full Rust 2024 migration because Rust 2024 is the durable direction for the project.

### Assistant Understanding

Facts:

- `src/crates/netipc/Cargo.toml` currently selects edition 2021.
- The manifest declares the NetIPC library plus interop and benchmark binaries located under `tests/fixtures/rust/` and `bench/drivers/rust/`.
- Netdata's Rust workspace already uses edition 2024 and Rust 1.91.
- A Rust 2024 compatibility lint check found reserved `gen` identifiers in benchmark drivers.
- The same check found edition-dependent temporary drop-order changes in SHM and UDS connection loops in benchmark and fixture binaries.
- Windows-only library compatibility changes are handled by SOW-0033, but full Windows target validation is still required for an edition migration.

Inferences:

- This work is broader than a manifest edit because edition 2024 changes keyword parsing, unsafe syntax requirements, and temporary drop scope.
- Mechanical suppression of the drop-order lint would be unsafe without proving that session and SHM destructors still run in the intended order.

Resolved unknowns:

- The user selected Rust 1.91 as the standalone MSRV to align with Netdata.
- Drop-order analysis showed the successful transport values move into
  longer-lived options; named `attempt` bindings now make all 12 retry-site
  lifetimes explicit and independent of tail-expression rules.
- Native Windows compatibility checking found no additional edition issue
  beyond the anticipated retry bindings and `unsafe extern` declaration.
- README, getting-started, Windows, integrator, and contributor guidance all
  required explicit edition/MSRV updates and were updated.

### Acceptance Criteria

- The standalone Rust manifest selects edition 2024 with an explicitly decided and documented MSRV policy.
- Every library, test, fixture, interop, and benchmark target declared by the manifest builds under edition 2024.
- All Rust 2024 compatibility findings are implemented or explicitly rejected with evidence; none are silenced without a behavioral explanation.
- POSIX Rust tests, coverage requirements, interop, and benchmarks remain valid.
- Native Windows or project-standard Windows validation covers Named Pipe, Windows SHM, typed service, cache, and declared Windows binaries.
- C/Rust/Go protocol and interoperability contracts remain unchanged and validated.
- A same-pattern search and artifact maintenance review cover all Rust targets and public guidance.

## Implications And Decisions

1. **Ordering - selected by the user: surgical backport first, full edition migration second.**
   - SOW-0033 must be committed and completed before this SOW moves to `current/`.
2. **Migration quality - user direction: Rust 2024 is a durable project direction.**
   - Treat this as a complete migration with compatibility and lifetime validation, not a warning-suppression exercise.
3. **MSRV - selected by the user: Rust 1.91.**
   - Match Netdata's workspace floor while using Rust 1.97.1 as the normal
     development compiler.
   - Do not raise the package floor to the latest compiler because vendored
     source must remain buildable by Netdata's Rust 1.91 workspace.
4. **Resource lifetimes - selected by the user: named `attempt` bindings.**
   - Make ownership and temporary destruction independent of tail-expression
     edition rules at all 12 symmetric POSIX and Windows retry sites.
5. **Toolchain enforcement - selected by the user: MSRV plus stable CI lanes.**
   - Do not add `rust-toolchain.toml`.
   - Add Rust 1.91 verification and retain forward verification on current
     stable, including Windows all-target compilation.
6. **Resolver and dependency scope - selected by the user: resolver 3 with the
   current lock.**
   - Accept resolver 3 as the edition-2024 default.
   - Do not refresh dependencies as part of this migration.
7. **Documentation - selected by the user: complete public toolchain guidance.**
   - Update the manifest, README/getting-started, Windows guidance, integrator
     skill, and AGENTS validation guardrail.
   - Do not change protocol specs or the vendoring skill because their
     contracts are unaffected.
8. **Windows validation - selected by the user: native validation on the
   dedicated test VM.**
   - Initial validation was limited to the preinstalled tools.
   - The user subsequently authorized autonomous test-VM changes and asked the
     assistant to react to failures directly. Rust 1.91.0 was therefore added
     as a non-default MSRV verification toolchain; Rust 1.97.1 remains the
     default.
9. **Formatting scope - selected by the user: separate semantic and style
   migrations.**
   - Add an explicit `style_edition = "2021"` project configuration so this
     SOW changes language semantics without reformatting unrelated production
     code.
   - Track the coordinated plugin-ipc and Netdata style-2024 migration in
     SOW-0035 rather than creating immediate vendor drift in this SOW.

## Plan

1. Apply the approved manifest, source, CI, and documentation changes.

3. Validate on the documented native Windows environment without installations.
4. Complete independent review, same-pattern search, artifact gates, and the

5. Commit only the exact migration files with the completed SOW move.
